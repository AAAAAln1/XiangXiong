# Object Model

## 对象 vs 非对象

对象是业务实体或能力边界，不是技术资源或漏洞类型。

正例：authentication boundary / OSS AK 权限边界
反例：/admin 路径（这是 surface）/ IDOR（这是关系类型）

---

对象用 attributes、relations、constraints、unknowns 描述。漏洞名是判断不是对象。关系要证。

**Unknown = 账上说不清的关系**（可差分证实/证伪），不是兴趣列表、不是洞名待办。

**Observation vs Fact：** 单次观察不是事实结论。观察 → hypothesis → 验证 → 事实。例：server: nginx/1.18 是 observation，不等于存在 nginx 漏洞。

**Experiment：** 用于消除会影响决策的不确定性，不是固定流程。单次探测不需要 create。

**冲突即记账：** 观察和当前模型打架或说不清 → 立刻留下可证伪 `hypothesis:`；禁止因「没马上打成」丢掉。可换主线，不可因新故事遗忘未闭合 hypothesis。

**对象同一性：** 路径 / query act / 函数名 / 近义业务名默认不是同一对象；合并要关系证据。回答「是否测过 X」须同一资源标识（path/method 等），近义名不顶替。

**Object Identity 判断：** 多个 surface 是否属于同一对象，取决于是否共享同一失败机制。

若多个 surface 在同一 Trust Boundary 内、服务同一业务能力、对同类攻击以相同方式失败 → 同一对象的多个入口，不必产生多条 hypothesis。

例：`/user/profile` 和 `/api/user/info` 若受同一认证机制保护 → 同一对象；`/admin/user/info` 需要管理员权限 → 不同对象，不同 Trust Boundary。

对象有邻接（上下游、入口、表示）。发现 A 不自动证明邻居存在。多入口是否同一业务对象、校验是否一致 = unknown。

目录/路由表/规范类 artifact：Known 与 Unknown 同时增加；有 vuln 也不等于未知已空。

多条结论可共享同一未证 premise；premise 倒了，依赖它的边要重估。证据不因被引用多次而变独立。

**Hypothesis 表达：**

一条 hypothesis = 一个核心关系。

目标：让模型快速理解未知关系，而不是拆成机械任务。

避免：
  "OSS AK 是否泄露数据并且可以访问其他 bucket/RAM/写入"

优先：
  "OSS AK 权限边界"
  
验证后记录：
  "List/Get/Put 成功，Delete 失败"

**但避免过度拆分：**

错误：
  - OSS AK 是否 List
  - OSS AK 是否 Get
  - OSS AK 是否 Put
  - OSS AK 是否 Delete

这些属于同一对象能力边界。

拆分依据：
  - 不同对象 → 可以拆
  - 不同关系 → 可以拆
  - 同一对象不同能力面 → 可保持一个 hypothesis

# Evidence Model

Observation != Fact。观察是特定请求上下文和来源层产生的结果，必须保留对应 artifact 与来源，并容纳替代解释。事实是观察在明确边界内能够支持的陈述，不得超出来源与上下文。

观察链可能经过执行器、网络、边缘层、网关、应用与后端；任一层都可能产生、改写、截断或隐藏结果。工具成功或失败首先是工具链事实，只有来源可区分时才能约束目标世界。摘要不是完整证据，未显示的 Artifact 内容仍可能包含更早出现的对象和关系。

孤立响应通常弱于受控差分。Baseline 与只改变一个相关条件的 Mutation 之间若产生稳定、可追溯差异，可以缩小替代解释；无差异只约束本次上下文与变量范围，不证明所有路径等价。

例如 403 可由 WAF、Gateway、App auth 或 route concealment 产生；这些只是替代解释，不是裁决。单次结果不能自动产生 `surface:`、`dead:` 或 `vuln:`。证据强度来自观察、来源和解释之间可追溯、可区分的联系，而不是标签、状态码或重复次数本身。

# Experiment Model

Hypothesis → Experiment → Observation → Conclusion 表达概念关系，不是固定工作流。Hypothesis 应可证伪并指向对象间关系；Experiment 用可观察差异检验该关系，尽量区分变量并记录 artifact。Observation 保留实际结果及其上下文。Conclusion 只陈述本实验对假设的支持、反驳或未区分范围，不外推未观察对象。

当观察存在多个内部解释时，只保留能解释现象的最小候选关系模型。每个候选必须导出不同的可观察预测；下一实验只改变能区分候选的变量。伪代码若有助于产生预测，可作为临时模型，但不是实现事实，不写入长期状态。

Baseline 与 Mutation 是可选的实验关系：它们用于区分“条件变化导致结果变化”和“结果本来如此”，而不是规定请求形式。实验还应暴露其依赖的 premise；当共享 premise 失效，相关实验结论必须按原证据边界重估。

负结果只关闭被实际区分的关系范围。版本、标签、状态码或有限变体不能替代部署条件、可达性和实际影响；未区分结果保留为 unknown，而不是伪装成完成。

这与现有 Experiment Contract 一致：实验 metadata 关联假设、动作、观察、artifact、结论与状态；这些字段建立可追溯性，不替代 Agent 的语义判断，也不改变数据模型。

--- cognition/surface_misalignment.md ---
# Surface Misalignment

Surface != Reality。可见表象可能由多个对象与边界共同产生；Data、Topology、Trust、Execution 是理解错位的四个镜头。观察只覆盖特定上下文，缺失、拒绝或成功都不能唯一确定背后的对象图。

Data 关注值从 Source 经 Transform 与 Validator 到消费者或落点的关系；Topology 关注对象的上游、下游、同级关系，以及入口、边界与实际服务的映射；Trust 关注身份、声明、验证者、策略与资源之间的信任边；Execution 关注输入最终由哪个 Interpreter 处理、以何种状态产生 Effect，以及中间约束是否保持。

同一输入可能被执行器、代理、网关、框架和应用解释为不同对象；同一业务对象也可能通过不同协议、表示或入口到达不同校验路径。层间解释差异和入口间约束不一致只产生候选 hypothesis，不自动证明绕过或漏洞。

四镜头用于揭示未确认关系、替代解释和共享 premise，不决定 memory 标签，也不规定测试顺序。


[ANTI-COMPRESSION]
- Similar identifier ≠ same object.
- Related behavior ≠ proven shared boundary.
- Successful path ≠ adjacent surface exhausted.
- Missing observation ≠ absence.
- Supported explanations should constrain the next experiment.
- Preserved unknowns do not retain equal priority outside the current explanation boundary.
