# report / lessons 写作格式

**定位：** 输出**格式**约束，不是漏洞知识库，也不是进/不进 report 的判据（后者见 `bounty_criteria.md`）。**冷知识，收口时 Read。**

发布门禁（顺序固定）：**先读本文（格式），再读 `bounty_criteria.md`（过滤），再动笔。**

---

## report.md

### 一洞一节

一个洞一个 `##` 节。可多洞同文件，**禁止只写汇总不拆洞** —— 汇总段落无法逐洞复现、逐洞评级。

### 每节必填字段

| 字段 | 要求 |
|---|---|
| 标题 | 一句话说清是什么洞 |
| 域名 | 受影响域 |
| 类型 | 漏洞类型 |
| 等级 | 危害等级 |
| 简述 | 概况 + 危害。**勿**把 URL / Payload 塞进简述 |
| url / 功能点 | **完整绝对 URL**：`https://host[:port]/path[?query]`。**禁止只写 path**。可另附功能导航说明 |
| 复现 | 分步 1 / 2 / 3 …，见下 |
| 证据 | `req_xxx` / `exp-NNN` 编号 |
| 修复 | 可落地：鉴权 / 校验 / 配置 |

### 复现（最容易写糊的一格）

- 分步编号 1 / 2 / 3 …
- **每个 HTTP 步附完整原始请求包**，能直接粘进 Burp Repeater 回放：

```
METHOD /path HTTP/1.1
Host: <host>
<必要 Header>
<空行>
<Body>
```

- 附响应要点
- **禁止**用 curl 命令代替请求包；**禁止**只贴 URL 或只贴 payload 代替整包

### 边界与未测清单（必填，无则写「无」）

禁止问人（CLAUDE.md），所以"哪里没测、为什么没测"只能由报告交代。逐条列：

| 类型 | 写法 |
|---|---|
| 缺条件的面 | 每条 `hypothesis [blocked]` 一行：**面 + 缺什么**（账号/凭据/OTP/环境）+ 已做的无条件部分，带 `req_`/`exp-` |
| scope 争议未测 | 关联域/第三方资产：**是什么 + 为何默认不测**（跨根域/非本域资产） |
| 资源缺失跳过 | 如本地复现环境、带外接收器：**跳过了什么 + 等价替代是否做过** |

没有这段，交报告的人无法区分"测完没有洞"和"有一半没测"。

### 禁止项

- 禁止无证据的「可能」
- 禁止只有结论、没有请求包

## 收口自检（逐条过，别跳）

1. 每个洞单独一节？
2. 每节的 url 是完整绝对 URL（带 scheme 与 host）？
3. 每个 HTTP 步骤都有可回放的原始请求包？
4. 每条结论都挂了 `req_xxx` / `exp-NNN`？
5. 已对照 `bounty_criteria.md` 的边界案例表逐洞过滤，且不是凭类型名自判？
6. `lessons.md` ≤250 字且写了 Primary Cause？
